Mikrodenetleyici Programlama: I2C / SPI / UART Haberleşme

Orta seviye bu derste; ARM Cortex-M tabanlı mikrodenetleyicilerde (STM32, NXP, ESP32) GPIO, kesme (interrupt) ve DMA kullanımını, ayrıca en yaygın üç haberleşme protokolü olan UART, SPI ve I2C'yi pratik örneklerle işleyeceğiz. Ön koşul: Elektronik ve Mikrodenetleyici Temelleri dersi.

Bu derste ne öğreneceksiniz? Register tabanlı GPIO kontrol, EXTI kesme, DMA transferi, UART/SPI/I2C protokollerinin fiziksel ve mantıksal katmanları ve bir sensör okuma örneği.

Öne Çıkanlar

  • Modern MCU'lar ARM Cortex-M0/M0+/M3/M4/M7 çekirdeklerini kullanır; 32-bit RISC işlemcidir.
  • Kesme (interrupt) kullanmayan gömülü sistem yoktur; polling yerine event-driven programlama tercih edilir.
  • DMA (Direct Memory Access), CPU yükünü azaltarak yüksek hızlı veri transferini mümkün kılar.
  • UART tek yönlü, SPI çift yönlü senkron, I2C çok cihazlı bus'tır.
  • STM32 CubeIDE, ESP-IDF ve Arduino en yaygın geliştirme ortamlarıdır.

Mikrodenetleyici Mimarisi

Bir mikrodenetleyici; CPU çekirdeği (ARM Cortex-M), Flash, RAM, çevre birimleri (GPIO, timer, ADC, UART, SPI, I2C, CAN, USB) ve saat sistemini tek çip halinde barındırır. Endüstriyel gömülü sistemlerde en yaygın seri STM32'dir (STMicroelectronics). Örnek konfigürasyon: STM32F411, ARM Cortex-M4F, 100 MHz, 512 KB Flash, 128 KB RAM, 3 UART, 5 SPI, 3 I2C, 1 ADC, USB, timer.

GPIO Kontrolü: Register Tabanlı

Bir LED'i D pinine bağladığımızı düşünelim (PA5, STM32 için). Yapılan işlemler:

  1. Clock aktif: RCC → AHB1ENR → GPIOAEN = 1
  2. Pin modu: GPIOA → MODER[10:11] = 01 (output)
  3. Çıkış tipi: OTYPER[5] = 0 (push-pull)
  4. Hız: OSPEEDR[10:11] = 00 (low speed)
  5. Pull-up/down: PUPDR[10:11] = 00 (none)
  6. Çıkış: ODR[5] = 1 (LED yak), = 0 (söndür)

HAL kütüphanesiyle: HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);

Kesme (Interrupt) ile Buton

Bir butonu PA0'e bağlayıp basıldığında LED durumunu değiştirmek için polling yerine EXTI kesmesi tercih edilir:

// CubeMX ile PA0 = GPIO_EXTI0, Rising Edge, Pull-up
void EXTI0_IRQHandler(void) {
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0);
}

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) {
    if (GPIO_Pin == GPIO_PIN_0) {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    }
}

Kesme ile buton okurken debounce (yaklaşık 30 ms yazılım gecikmesi) mutlaka uygulanmalıdır; aksi hâlde bir baskı 5-10 kez algılanabilir.

UART: Seri Haberleşme

UART (Universal Asynchronous Receiver-Transmitter), iki cihaz arasında asenkron seri haberleşme sağlar. Tipik parametreler: 9600 bps, 8 data bit, no parity, 1 stop bit (8N1). RS-232 fiziksel katmanla ±15V, RS-485 ile ±5V ve fark tabanlı çalışır. TTL seviye 3,3V / 5V.

HAL_UART_Transmit(&huart1, (uint8_t*)"Hello\r\n", 7, 100);

// DMA ile:
HAL_UART_Transmit_DMA(&huart1, buf, len);

SPI: Yüksek Hızlı Senkron

SPI (Serial Peripheral Interface), 4 hatlı (MOSI, MISO, SCLK, CS) senkron protokoldür. Aynı bus'ta birden fazla cihaz olabilir; her cihazın kendi CS (Chip Select) hattı vardır. Hız 10-50 MHz'e ulaşır. Örnek uygulama: SPI Flash, OLED ekran, SD kart, ADC (MAX11040 gibi).

uint8_t tx[2] = {0x01, 0x02};
uint8_t rx[2];
HAL_GPIO_WritePin(CS_PORT, CS_PIN, GPIO_PIN_RESET);
HAL_SPI_TransmitReceive(&hspi1, tx, rx, 2, 100);
HAL_GPIO_WritePin(CS_PORT, CS_PIN, GPIO_PIN_SET);

I2C: Çoklu Cihaz Bus'ı

I2C (Inter-Integrated Circuit), sadece 2 hat (SDA, SCL) kullanan çok cihazlı bir bus'tır. Standart 100 kHz, Fast 400 kHz, Fast+ 1 MHz. Her cihazın 7-bit adresi vardır (128 cihaz teoride). Örnek uygulama: EEPROM (24LC256), sıcaklık sensörü (LM75, BMP280), IMU (MPU6050), RTC (DS3231).

// LM75 sıcaklık sensörü örneği
uint8_t reg = 0x00;  // Temp register
uint8_t data[2];
HAL_I2C_Master_Transmit(&hi2c1, 0x90, ®, 1, 100);
HAL_I2C_Master_Receive(&hi2c1, 0x90, data, 2, 100);
int16_t temp = (data[0] << 8 | data[1]) >> 5;
float celsius = temp * 0.125f;

DMA (Direct Memory Access)

DMA, çevre biriminden RAM'e (veya tersi) CPU müdahalesi olmadan blok halinde veri taşır. CPU sadece transfer başladığında ve bittiğinde meşgul olur; arada başka işleri yapabilir. ADC gibi yüksek hızlı örneklemede (kHz-MHz), UART receive gibi asenkron olaylarda ve SPI/I2C toplu transferlerde şarttır.

Debug Araçları

  • ST-Link V2/V3: STM32 için standart debug + programlama
  • J-Link: Segger'ın çoklu MCU destekli profesyonel debugger
  • Salae Logic Analyzer: UART/SPI/I2C sinyal analizi
  • Osiloskop: Fiziksel sinyal kalitesi ve timing
  • RTT (Real-Time Transfer): printf tabanlı hızlı debug
